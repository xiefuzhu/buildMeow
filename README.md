# 建喵！

离线 Minecraft 方块像素画与地图画生成器：选择图片，生成可建造的作品，并输出图纸、材料清单和投影文件。

## 自动构建与发布

GitHub Actions 配置位于 [windows-release.yml](.github/workflows/windows-release.yml)，固定使用 Flutter 3.47.7 / Dart 3.13.5 和 Windows x64 构建环境。

- 推送 `main`、提交到 `main` 的 PR 或手动运行 Actions，执行两包静态检查、核心测试及应用测试，成功后构建安装包与便携 ZIP。应用测试沿用现有脚本，只重试原生测试进程崩溃，保留测试日志。
- 在 Actions 的 **Windows build and release → Run workflow** 中可指定测试版版本号。手动运行只生成构建产物，不发布 Release。
- 推送 `v1.0.0-beta.3` 这样的版本标签，在检查、构建和打包全部成功后，自动创建 GitHub 预发布并附加安装包、便携 ZIP、SHA-256 校验文件及载荷清单。当前安装器面向测试版，版本号格式为 `X.Y.Z-beta.N`。

在已经提交且准备发布的代码上执行以下命令（后续发布请递增版本号）：

```powershell
git tag v1.0.0-beta.3
git push origin v1.0.0-beta.3
```

日常构建产物和测试日志在对应 Actions 运行页面保留 14 天；版本标签发布的文件可从 GitHub Releases 下载。上传发布使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需配置个人访问令牌。仅发布任务具有仓库内容写权限。

本地完整打包可在仓库根目录执行（需 Flutter、Visual Studio C++ 工具链及 Inno Setup 6.5+）：

```powershell
powershell -File app/tool/build_release.ps1 -AppVersion 1.0.0-beta.3 -BuildNumber 3 `
  -Compiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

输出位于 `app/build/installers/`。便携 ZIP 包含 C++ 运行库，解压后保留完整目录。使用 `SHA256SUMS.txt` 核对安装包及 ZIP；`.sha256.json` 和 `.payload.json` 保留详细安装器校验信息。CI 构建与测试通过只证明自动检查和打包完成；真实桌面交互、安装卸载和关闭生命周期仍需按既有验收脚本检查。

## 两种作品

- **方块像素画**：使用方块顶面贴图的平均颜色，生成单层平面。贴图预览按标准光照近似，不能当作地图物品的画面或游戏截图。
- **地图画**：使用游戏地图色表。阶梯模式以北侧相邻方块的高度差控制明暗，跨地图接缝连续；单层模式按同高方块的地图颜色重新配色，全部方块和北侧参照行处于同一高度。可在生成参数中选择，或在导出页切换并重新生成。

预览、图纸与投影共用 `MapPlan`。地图色域有限，配色是近似，不保证原图颜色零误差。新设置默认等比适应并留边，用户可主动切换等比裁剪；已有合法构图设置会保留。

生成仅使用当前支持的候选方块。水、重力、依赖支撑及未确认的候选不会自动参与生成，参数面板可查看不可用原因。方块像素画的导出状态与用于取色的顶面方向一致。

## 使用流程

五个入口：生成、图纸、材料、导出、设置。宽窗口提供画布与参数栏，较窄窗口使用参数抽屉，窄屏采用底部导航。高级配色默认折叠；调色板与材料均支持搜索。

参数改变后 220ms 自动生成，一次只运行一个任务；图片或生成参数变化时终止过期计算，过期结果不会发布或导出。材料页区分画面、表层、实心用量。关闭候选会重新配色，隐藏材料只影响预览与图纸显示，不改变导出内容。

导出支持 `.litematic`、Sponge v2 `.schem`、PDF、PNG 和带 UTF-8 BOM 的 CSV。导出的材料统计包含所选填充和参照行，与对应投影一致。PDF 总览保持比例，分图显示区块线，长图例和材料表自动分页；大 PNG 总览明确标记为缩略图，逐张图纸保留选定分辨率。

地图画默认包含北侧参照行；方块像素画不需要。关闭地图画参照行后需自行补建。作品内坐标从零开始；地图画在游戏中的西北角应对齐 `X、Z = 64 + 128k`，包含参照行时地图第一行位于投影 `z = 1`。

投影导出在分配密集结构前检查内存，默认预算 1GiB；超出时提示减小尺寸，不裁切作品。预览最长边限制为 4096px。导出按格式分批处理，PNG 逐张生成并等待保存；结果仅保留名称、大小、路径和状态，不保留文件字节。同名文件可选择覆盖、改名或跳过，每个文件分别报告保存结果；后续格式生成失败不会丢失已经保存的结果。

## Windows 悬浮、快捷键与托盘

标题栏的「悬浮图纸」、设置页入口或托盘菜单可以进入悬浮模式。它使用同一份生成结果和图纸状态，默认 480×620，最小 360×360，保持置顶；支持拖动、缩放、翻页、缩放图纸及点选方块。退出时恢复普通窗口的大小、位置和最大化状态，返回进入前的页面。窗口显示时会尽量调整到当前显示器工作区，避免移除显示器后找不到窗口。

| 操作 | 默认全局快捷键 |
| --- | --- |
| 显示 / 隐藏窗口 | `Ctrl+Alt+M` |
| 进入 / 退出悬浮图纸 | `Ctrl+Alt+F` |
| 从悬浮返回普通窗口 | 窗口内按 `Esc`，或点击标题栏的退出悬浮按钮 |

全局快捷键在窗口隐藏或失去焦点时仍生效。设置 → Windows 桌面可关闭快捷键、换用增加 `Shift` 的备用组合键，或重新注册。设置页分别显示两个快捷键的注册结果；错误码 1409 表示组合键已被占用。部分注册失败时，成功注册的快捷键和托盘仍可使用。

托盘单击或键盘激活显示窗口，右键菜单提供显示、隐藏、切换悬浮和退出。默认关闭按钮直接退出；可在设置页开启「关闭按钮隐藏到托盘」，之后从托盘菜单退出。退出等待设置保存，保存失败会重新显示窗口以便恢复。托盘不可用时禁止隐藏，关闭按钮回退为退出；Windows 任务栏重新创建时会尝试恢复图标，恢复失败则显示窗口。应用退出释放图标和快捷键。

游戏建议使用窗口化或无边框窗口模式；独占全屏是否允许其他窗口置顶由游戏和系统决定。当前悬浮图纸使用一个窗口，不保存浮窗位置、不支持鼠标穿透，也不修改游戏输入。

## 自适应与无障碍

- 页面按照可用宽度、高度和字体尺寸选择侧栏或底部导航；参数选项放不下时纵向排列。短窗口中的图纸工具栏和读数分别滚动，画布保留在中间。
- 设置 → 外观提供高对比度和 100%–200% 字体缩放；字体缩放叠加系统设置并保留系统的非线性缩放，不锁定系统字号。系统高对比度也会自动选择高对比度主题。
- 图纸可用 `Tab` 聚焦，方向键逐格选择，`Home` 回到当前图纸左上角，`Enter` 开始选格。读数区提供方块、坐标和高度并标记为实时语义区域。
- 材料数量随窄屏、大字体移到名称下方，隐藏和独显状态包含文字提示；搜索无结果时显示说明。计数按钮提供明确的语义标签。
- Flutter 3.47 的滑块浮层存在上游语义树问题。本项目让每个滑块持有独立 Overlay，保留 Material 滑块、键盘操作和语义；背景见 [Flutter #190357](https://github.com/flutter/flutter/issues/190357)。测试脚本同时检查原生可访问性桥接日志，不能只凭 Dart 层没有异常判断通过。

## 设置保存

生成参数（含单层模式）、主题、无障碍选项、Windows 快捷键和关闭行为、隐藏/独显方块、导出目录、格式、文件名前缀和构建选项会自动保存；参照行选择按作品模式分别记忆。Windows 配置位于 `%APPDATA%\com.buildmeow\建喵!\preferences.json`，与可执行文件位置无关。首次运行会迁移旧版 `shared_preferences.json` 中的兼容值，保留原文件；图片本身不保存。

写入使用文件锁并合并最新配置，正常关闭前等待保存完成。失败时设置页显示错误并提供重试，关闭会等待用户恢复保存。迟到的配置恢复不会覆盖刚修改的选项。

## 流水线性能基准

在 `app/` 编译并运行纯 Dart AOT 基准（不会启动或替换桌面应用）：

```powershell
dart compile exe tool/benchmark_pipeline.dart -o build/benchmark_pipeline.exe
./build/benchmark_pipeline.exe --sizes=1,5,16 --output=build/benchmarks/pipeline.json
```

默认覆盖两种作品、无抖动/Floyd–Steinberg、CIE76/色度加权/CIEDE2000，共 36 个组合。可用 `--kinds=mapItem`、`--dithers=none`、`--metrics=cie76` 缩小范围；`--timeout-seconds=120` 控制每个样本的进程总时限。完整矩阵可能较久，建议按尺寸分别运行并使用不同输出文件。每个样本使用独立进程；报告逐例落盘，失败和超时不视为成功，存在未完成样本时返回非零退出码。

分阶段计时覆盖解码、缩放、调色板、量化、高度求解、作品模型、地图渲染、贴图预览、统计及误差计算。使用固定种子的 2048×2048 渐变、硬边和噪声图；计时不含资源加载与测试图准备。峰值 RSS 是包含准备工作的整个进程内存，不是 Dart 堆或某一阶段的净分配，也不是包含 UI 和 isolate 传输的 Flutter 端到端性能。冷启动单次样本用于定位方向，不当作稳定的性能保证。

2026-10-19，Windows x64 / Dart 3.13.5 的 AOT 初始基准：36 个组合中 26 个完成、10 个达到单样本 120 秒上限。1×1 耗时约 0.62–5.43 秒；5×5 完成的样本约 4.99–110.50 秒。16×16 完成的方块抖动样本约 68.87–69.72 秒，量化约占 92%，峰值 RSS 约 296–297 MiB；地图画色度加权抖动样本约 109.03 秒。大作品首先受配色计算限制，不能只靠缓存解码解决。

原始报告位于 `app/build/benchmarks/pipeline_1.json`、`pipeline_5.json`、`pipeline_16.json` 和 `pipeline_16_remaining.json`。16×16 首批运行触及外层总时限，报告保留已完成的 10 个样本，最后两个组合另批运行，没有重跑超时样本。此基准尚未测量本轮导出内存改动的峰值收益。

本轮 Windows 发布版位于 `app/build/releases/pdf_flat_persistence_fix/`，需保留整个目录。旧版 `blueprint_drag_fix/` 保留；使用隔离构建目录生成，原 `runner/Release/` 中的程序未替换。旧 PDF 需用新版重新导出。

**尚未游戏实测**：Litematica / WorldEdit 实际加载，以及建造后的地图颜色。当前数据目标固定为 Minecraft Java 26.1.2，不能根据内部往返测试宣称其他版本兼容。Android 本轮按要求不纳入验收；真机操作与动态取色尚未验证。

## 后续优化建议

以下为结合当前代码和外部示例整理的后续方向；性能基准、过期计算取消和分批导出已推进，其余仍未实现：

1. **优先补工程文件与建造进度**：把原图、生成参数、数据版本、当前图纸和已完成区域保存为带版本号的工程。现有配置只记选项，关闭后仍需重新导入图片；悬浮图纸现在已能承担逐格对照，保存分图或分区进度会更直接地改善长时间建造体验。工程格式应先定义迁移与缺失素材恢复行为。
2. **依据测量继续优化重复生成**：已补 1×1、5×5、16×16 的实际流水线 AOT 基准；生成设置或图片变化时会终止旧工作 isolate，保留防抖和过期结果校验。大作品量化仍慢，后续应先定位配色热点；常驻工作 isolate、解码图像和调色板缓存尚未实现。[Flutter isolate 指南](https://docs.flutter.dev/perf/isolates)给出了长期工作 isolate 的适用场景；是否值得改造应由测量决定。
3. **继续验证分批导出收益**：`executeExport` 已按格式分批生成和保存，PNG 逐张处理，UI 只保留无字节的结果摘要，保留投影 1GiB 检查和逐文件状态。两种投影分别构建结构，会增加同时导出两种格式的计算量；需进一步度量这一取舍和图纸导出的峰值内存。整批导出取消尚未实现。
4. **建立游戏内验收样本，再扩展方块能力**：为单层、阶梯、参照行、跨图接缝和顶面方向保存小型固定样本，在目标版本的 Litematica / WorldEdit 中加载并比对建造结果及地图。参考 [Litematica 的放置流程](https://github.com/maruohon/litematica/wiki/Basic-Operations)。[MapartCraft 的支撑构造分析](https://github.com/rebane2001/mapartcraft/blob/master/docs/supportBlocks.md)展示了支撑、重力与相邻高度的相互影响；水深、重力方块和自动支撑应建立单独的能力模型与实测用例后再开放。
5. **把回归检查固化到持续集成**：核心检查、应用独立测试脚本、Windows 构建、无障碍大字体回归和发布资源校验可分层运行。原生崩溃、断言失败和环境热键占用应分开报告，保留首次日志；真实快捷键与桌面交互验收仍需可交互 Windows 会话。[Flutter 无障碍测试指南](https://docs.flutter.dev/ui/accessibility/accessibility-testing)可作为后续扩展语义标签、对比度与点击区域检查的依据。
