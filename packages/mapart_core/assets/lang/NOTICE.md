# Provenance of the files in this directory

## `zh_cn_blocks.json`

- **Upstream:** Minecraft Java Edition's own language file,
  `assets/minecraft/lang/zh_cn.json`, as mirrored by
  <https://github.com/InventivetalentDev/minecraft-assets>
- **Revision:** branch `26.1.2` (the release `versions.json` targets)
- **Retrieved:** 2026-10-14
- **Bytes:** 527002 (whole file, as vendored at `tool/data/zh_cn_26_1_2.json`)
- **SHA-256:** `16F7BAEFF4C283273E0736C9B8D4BD645E52CF4B98B810B57CB7F419AC187FA7`
- **Generated by:** `tool/gen_block_names.dart`
- **Rights:** the strings are Mojang's translations of Mojang's block names,
  shipped here as a data table so the app can label a block the way the game
  does. Nothing about the file is claimed as ours; it is not a creative work
  being redistributed, it is an identifier-to-name lookup.

The generator keeps every `block.minecraft.<id>` key whose `<id>` has no
further dot, which is 1184 of the file's 8121 keys; the other 700 `block.*`
keys are sub-entries (a sign's front text, a potted plant's contents) that name
something other than a block.

Do not hand-edit `zh_cn_blocks.json`. Re-run the generator, and update the
SHA-256 above if the vendored source changes.

### Why not MapartCraft's names

The colour table next door carries a `displayName` per block, and it is English
and stops at 1.20. The interface is Chinese and the palette now reaches blocks
added long after that, so the names come from the game instead — one source that
covers every block the palette can offer.

### Coverage

`tool/gen_block_names.dart` also checks the table against the palette the app
actually builds for `26.1.2`, support-requiring blocks included. It reports
every palette block with no Chinese name; the current answer is none. Two blocks
the extractor once surfaced, `item_frame` and `glow_item_frame`, are entities
rather than blocks and are filtered out of the palette entirely — see
`lib/src/block_colours.dart`.
